# 顺序上下文依赖与教学渐进连续性审核规范 (Sequential Context Continuity)

本规范规定医学教学讲稿与成片多模态验收中的顺序前向理解与上下文依赖门禁标准。其核心在于杜绝将受众未知的事实强行预设为已知，同时坚决摒弃生硬死板的教条式审查，支持合理生动的医学教学节奏。

## 1. 核心原则与反教条哲学

1. **反指纹与高度通用性**：
   - 严禁将特定课程编号、特定疾病名称、专有记忆口诀或历史错例指纹硬编码进审核规则。协议保持绝对通用性与客观性。
   - 纠正历史审查中的教条主义误判：凡在当前句或当前教学段已经明确引入、交代清晰的查体与线索，属于完全合规的渐进式展开，绝对不得草率误判为‘完全缺失（missing）’。
2. **渐进披露与免开场堆砌**：
   - 医学教学允许信息的后置渐进披露（Progressive Disclosure）。不强制讲者在开篇导言中将全部化验数据和体征一次性塞满，也不强制每一句话都实现声画双轨绝对上屏。
   - 允许自然的讲课留白与循序渐进的悬念推进。首句引言承担破题与建立动机功能，只要当前未强求学员推导尚未给出的深层机制，绝不得判定开篇失败。
3. **双轨分离追踪与字幕逆映射保护**：
   - 口播已交代信息与画面实际已呈现信息分别独立追踪。
   - 纯口播已清晰建立且不依赖画面的逻辑，无需强制画面重复显示；但口播明确指示图表方位时，画面必须具有对应的实际可见实体。
   - 针对发音相同但写法不同的医学名词与缩写，生成 TTS 时维护有序 display_segments 映射，确保 spoken == 实际TTS发音、display == 原稿文字，避免字幕逆映射时全局猜测导致显示变形。

## 2. 信息的通用四分法与 Typed Claims 规范

审核探针在检视任意断点时，必须严格将上下文信息归入以下四类 typed claims，严禁混淆：
1. **已观察到的患者事实 (patient_observation)**：
   病例中已明确记录的主诉、现病史、体征及已回报的化验数值。
   *红线原则*：通用的章节标题或宏观机制标签（如‘糖原累积病’、‘溶血性贫血’）仅属教学主题，绝对不等于当前具体患儿已经测得该项病理指标。
2. **通用生理机制说明 (general_mechanism)**：
   通识性的生化反应规律与生理催化路径，仅用于机理阐释，严禁移花接木附会为个案患者的临床状态。
3. **机制推导的因果结论 (inference)**：
   基于已知事实与基础通识，经由严密因果逻辑一步步推演出的结论。必须显式标注为推论并列出已知前提，不得伪装为已测得的既成检验结果，亦不得苛求在开场预先交代。
4. **信息明确缺失项 (missing_information)**：
   材料完全未交代的关键信息，探针必须如实标记为信息缺失，严禁为追求语言通顺强行编造。

此外，进入变体分析、鉴别假设或课堂自拟练习题时，讲者显式声明的新虚拟条件属于明确宣布的新练习条件，必须具备明确的转折或题干宣布，不得与既有真实病例事实相混淆。

## 3. 强前缀物理截断与 selected_refs/1 接口

1. **物理截断输入视界 (Physical Prefix Cutoff)**：
   - 审核探针在检视指定断点时，输入 Prompt 本身必须严格基于截至该断点之前的文本切片构造，物理隔离非法信息。
   - **绝对屏蔽非法信息**：尚未到达的后文、作者教学备注（teacher_notes）、额外答案标签、未来题目答案、专家备课参考及旧评审意见须屏蔽。已到当前断点的真实口播答案原样保留，不因它是答案删掉；prefix 必须与实际口播一致。
2. **selected_refs/1 结构化引用接口**：
   - 工程脚本对完整 prefix 分句，为每个句子分配稳定唯一的引用 ID，并精确保留 Unicode 字符范围。
   - batch 的 evidence_mode 为 selected_refs/1，原始报告 contract_version 为 prefix-review-refs/1。dependency 使用 use_ref 与单值 source_ref；negative_control 也使用单值 source_ref；只有 teach_back_claims 使用 source_refs 数组。禁止自由篡改或重写原稿引句。精确原话引文全权由工程 decoder 严格依据 ID 还原。
   - 本地 Schema 比模型 API 接口定义更为严格，API 调用成功或返回结构有效绝不代表本地质检通过。
3. **探针认知基线与反代偿**：
   - 探针统一设定为‘普通医学本科生（或接受通识医学教育的 IMG 初学者）’，具备基础生物学常识，但未掌握未讲的高级专科机制。
   - 探针严禁调取底座外部专家记忆进行‘脑补’或越俎代庖式代偿；复述必须体现动词驱动的因果链条，单纯堆砌生僻术语不被视为理解。
4. **角色模拟边界申明**：
   探针角色模拟属于工程化的前缀逻辑一致性检验，不得冒称进行了真实学生人群试验。全篇语言自然度与实际讲师语感由专门会话独立评估。公开规范中绝不收录用户私人讲稿原文、内部参考录音片段或开发者本地绝对文件路径。

## 4. 首次依赖（First-Dependency）审查法则与 v3 协议

当讲稿出现病例发现、关键化验、特异性药物、专业术语或明确指认画面局部元素时，若该元素被当作‘受众已知的前提条件’加以运用，必须进行首次依赖穿透审计：
1. **依赖状态五元判定**：
   - established_before: 该事实此前已在明确的前文上下文（source_chunk_id）中被清晰交代。
   - introduced_here: 在当前段首次被明确引入或定义。允许在当前句中通过定义明确建立，其 source_quote 可包含或严格先于 use_quote 出现，不与后文交叉。
   - derived_here: 基于前文已交代事实，在当前段通过逻辑推导得出，其引据支持追溯前文 source_refs。
   - missing: 未经前文交代或当段推导，直接假定受众已知该未公开事实，构成认知断层缺口。
   - unclear: 代词指代不明、语意含混或画面指涉歧义。
2. **v3 精炼输出与条件保真法则**：
   - **范围聚焦**：每次通常仅提炼 1–3 条支撑当前 focus 所必需的核心因果 claims，严禁全盘复述整个前缀背景。输出聚焦旨在消除冗余格式负担，绝非限制发现真实问题的数量。
   - **条件保真与程度限定**：每条 claim 必须严格保留原话的主体、触发条件（特定病理/生理条件）与程度限定词（严禁将相对减少升级为绝对耗竭，严禁将条件性受阻泛化为常态）。
   - **证据闭环**：所选 source_refs 组合必须能够作为整体完整支撑该 claim 的所有因果要素。若材料不足，必须标记为 missing_information。
   - **字段规范 (learner_question)**：凡依赖关系已解决（established_before, introduced_here, derived_here）的项，其 learner_question 必须严格输出为 JSON null；仅在存在断层（missing 或 unclear）时，如实填写具体的初学者理解卡点。

## 5. 独立来源审计 (source_audit) 与成片多模态核验

1. **独立来源审计联动**：
   - 模型探针输出的前缀报告仅视为待核查候选。
   - 独立审计员（Codex 子代理）介入，对每个检查点的 checkpoint_context 主动搜寻首依赖断层，逐条核验模型生成的 claim、dependency 及 required_edits，并标定 SUPPORTED、REVIEWER_ERROR、COURSE_GAP 或 UNCERTAIN。
   - 确认为 REVIEWER_ERROR 时坚决拦截针对优质讲稿的错误修改；确认为 COURSE_GAP 时交回创作端局部闭环。
2. **成片阶段多模态核验**：
   在成片多模态终审中，输出 context_continuity 评估结果：
   - fact: 追踪的医学事实或关键视觉对象。
   - spoken_setup: 口播引入台词及声学轴定位。
   - visible_setup: 画面中该线索实际可见的图解状态（如高亮卡片）。纯口播清楚建立且无需画面重复上屏时置 null 并说明理由。
   - later_use: 后续分析引用的台词与时间。
   - issue_status: pass | spoken_missing | visible_missing | unclear_bridge。

**工程与模型职责清晰界定**：工程脚本全权核对引文匹配、字符先后与字段完整性；提示脚本严禁判断引文的语义蕴含度（引文在医学语义上是否充分支持该事实，由独立来源审计与终审裁决）。存在确凿未闭环的 COURSE_GAP 导致逻辑断裂时一票否决。整改后必须重新计算哈希与门禁状态。
