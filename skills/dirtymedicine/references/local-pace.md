# 确定性局部语速突变筛查规范

本规范定义长课英文音频局部语速突变与短窗冲快的工程筛查标准、执行命令与人工复听放行机制。

## 1. 工具定位与核心原则
- **确定性工程筛查**：由独立脚本 `scripts/detect_local_pace.py` 基于词级时间戳与波形活动度进行纯算法比对，全程 0 次 LLM 调用，不修改音频、不插停顿、不进行局部拉伸。
- **禁止 LLM 数值裁决**：明确禁止为数字语速突变、短窗速率对比、阈值判定或静音测速调用 Gemini/agy，亦不得将此类数值证据的确认或处理依赖于 Gemini 批准。
- **分工明确**：Gemini/agy 继续负责讲稿创作、发音正确性、整体连贯语气与多模态视听验收；若模型听审偶然指出语速急促，必须返回工程测量数据与人工上下文复听，严禁将 LLM 估算速度作为数值裁决。

## 2. 输入与前置条件
- **音频格式**：单声道 (mono) PCM16 WAV 文件。
- **词级对齐 ASR**：必须提供包含词级时间戳与置信度的 JSON 文件（格式符合 `segments[].words[]`，包含 `word`、`start`、`end`、`probability`）。
- **SHA256 强校验**：ASR JSON 顶层 `source_sha256` 必须与待测 WAV 文件的实际 SHA256 逐字节哈希一致；哈希不匹配时脚本强制拒绝运行。
- **ASR 资产复用**：既有已验证的词级 ASR 直接复用，无需为了检测重新调用任何模型；在仅执行纯尾裁且音频起点未发生偏移时，沿用既有词级时间戳并同步更新哈希映射。

## 3. 依赖与执行命令
- **依赖环境**：
  - 依赖库：`numpy>=1.26,<3`, `cmudict==1.1.3`（定义于 `scripts/pace-requirements.txt`）。
  - 底层音频读取由既有 `scripts/standardize_course_pacing.py` 的 `load_pcm` 提供。
  - 执行前确认 Python 环境：优先使用项目既有 `.venv`；全新环境可通过 pip 安装：
    ```bash
    pip install -r "<skill-dir>/scripts/pace-requirements.txt"
    ```
- **执行命令**：
  ```bash
  python "<skill-dir>/scripts/detect_local_pace.py" \
    --audio narration.wav \
    --asr narration.asr.json \
    --policy "<skill-dir>/scripts/local-rate-policy.json" \
    --out local-pace-check
  ```

## 4. 测算指标与算法逻辑
- **音节代理计数**：采用 CMU 发音词典 (`cmudict==1.1.3`) 提取第一发音中的数字元音标记，作为音节代理估计，非声学精确音节；未登录词 (OOV) 采用元音字母组规则估算，并显式标记为 `vowel_group_estimate`。
- **不可用标记过滤**：纯数字或含数字的 token 不支持音节测算（标记为 `unsupported_number_or_token`）；零时长（`end <= start`）、对齐置信度低于配置阈值的词从有效窗口中排除，不纳入有效分析窗口。
- **波形纯发声时间计算**：在分析用静态增益标准化后，按照配置中的 RMS 窗口、能量阈值及最短低能量区间时长扣除静音，估算窗口内的有效发声时间。此为能量规则代理测量，原音频保持不变。
- **滑动多窗与对比基准**：
  - 滑动分析 6、8、10 词连续短窗，排除跨句符号与过大词间停顿。
  - 局部对比：与前后 25 秒上下文基线中位数比对（排除自身及紧邻 1 秒内重叠窗口）。
  - 全局与句首对比：与全课有效窗口中位数比对；句首窗口额外与紧邻前一有效窗口比对。
- **策略与阈值管理**：所有对比阈值（如局部上下文比率、单侧对比比率、句首突变比率）集中维护于 `scripts/local-rate-policy.json` 中，以候选状态管理，严禁在代码中硬编码为普适生理标准。

## 5. 输出文件结构
脚本执行后在输出目录生成以下产物，记录音频、ASR、策略与检测脚本的 SHA256 及 cmudict 版本：
- `report.json`：机器可读完整报告，包含元数据哈希、全课分析统计、跳过窗口统计、局限性说明及合并后的候选清单。
- `candidates.csv`：扁平化候选表格，列出 rank、起止时间戳、短语文本、局部对比倍率、全课对比倍率、单侧对比倍率、最低对齐概率及候选状态。
- `review.html`：本地轻量复听页面，提供各候选区段及前后各 4 秒上下文的快速试听按钮，便于人工审查。

## 6. 适用范围与边界
- **语言范围**：当前检测器及其音节代理规则仅验证 `en-US` 英文，**严禁外推到中文或其他语言**；CLI 中文或其他语种不得谎称已验证。
- **未覆盖处理**：若缺少可信词级 ASR，或遇到不支持的语言，必须如实报告“未覆盖/需准备对齐数据”，**严禁给出 clean/无异常的放行结论**，更不得将对齐或测速任务甩给 Gemini。
- **结果解释**：报告生成仅代表数值筛查完成，不得向用户宣称“已在外部浏览器完成 review.html 实际播放测试”或“全轨音频绝对完美”。

## 7. 候选筛查与人工复听放行
- **候选非确诊**：脚本检出项的状态严格标定为 `review_candidate_not_confirmed_defect`（复听候选而非确认缺陷）。全课检出候选绝不等于存在缺陷，零候选亦仅代表可靠短窗未触发当前策略配置。
- **上下文复听研判**：由 Codex 或人工通过 `review.html` 或工程宿主试听候选及其前后 4 秒上下文，核对真实波形与 ASR 对齐质量：
  - 辨别功能词语流：常用介词、代词、连词（如 "think that the"）天然发声较快，属于自然语言语流特征，严禁机械按逐词速度判错。
  - 保护主谓语流与原声重音：严禁在紧密主谓结构（如 "liver must"）间粗暴强插停顿切断语流，更严禁采用局部时间拉伸破坏母带原有顿挫。
- **严禁过度处理与自动平速化**：绝对禁止通过全自动算法将所有检出候选强行拉平为恒定语速。
- **独立工程裁决**：数值候选是否需要处理，由 Codex 与人工上下文复听证据研判，**这项数值检查绝不需要 Gemini 审批或盖章**。完整音视频的自然度、发音与教学验收仍按既有流程执行；低置信度及跳过区间必须如实保留记录。

## 8. 实证数据与基准测试
- **生产案例定位**：在 B02 最终交付 WAV 中，测试短语 `"Many students think that the liver"` 准确命中于 `99.732376–101.146403` 秒区间；其相对于邻近上下文参考倍率为 `1.32057`，相对于紧邻前窗倍率为 `1.43788`；该短语在原生未校准生成轨中亦准确命中于 `91.69–92.99` 秒。
- **候选规模认知**：B02 全课共检出 15 处候选；这不等于已确认 15 处缺陷，也不表示已经对所有候选完成听感判定。当前案例与行为测试不构成大规模灵敏度或特异度评测。
- **工程行为测试覆盖**：检测器已通过 9 项确定性行为测试（统一语速不变性、整轨倍速缩放、音量增益鲁棒性、长停顿隔离、植入句首冲快检出、零时长与低置信度跳过、无声/破损时间戳异常报错、CMU 词典音节计数准确性），验证了工程稳定性与边界健壮性。

## 9. 重测触发规则
当满足以下任一工程条件时，必须对最终成片音轨重新执行确定性局部语速突变筛查：
1. 讲稿改动后重新调用 TTS 原生生成完整音轨；
2. 音频进行了整轨 tempo 校准、增益调整或分段修剪；
3. 字幕或词级时间戳进行了重新对齐与映射更新。
