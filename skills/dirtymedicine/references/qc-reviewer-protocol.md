通用医学课程顺序理解与首次依赖审核协议

一、协议定位与设计哲学
本协议旨在为医学视听教学脚本建立通用的“前向顺序理解”与“首次依赖（First Dependency）”自动化/半自动化质检标准。本规程主要服务于两类工程场景：一是历史正反例标定样本的无偏盲测，二是新撰课稿在时间轴推进过程中的增量前缀（Prefix）阻断式审核。协议将语言认知规范与工程执行清晰解耦：本规范确立医学认知递进逻辑与判定红线，具体调度、分块截断与音画时序工程由执行系统承载。
本协议恪守高度通用性与反教条原则：严禁将任何既有课程编号、特定病种命名、专有记忆口诀、历史错例指纹或预期标签编入协议。测试样本与黄金答案由工程管线外部隔离保管，审核探针在测试全程保持完全盲态。协议坚决反对“机械找茬”：不强求讲稿每一句话都必须有前置证据锚点，不强制推行声画双轨绝对上屏，允许生动自然的教学留白。协议只聚焦于是否存在阻断当前学习者理解的真实认知缺口。需明确，本协议无法替代全课完篇后的自然度评审或成片MP4的音画综合终审。

二、审核探针角色定义与认知基线
审核探针统一设定为“普通医学本科生（或接受简明英文教学的国际医学毕业生/IMG）”，普通英语难度以公认的清晰通俗授课语言为基准。其认知能力与权限严格受限于以下边界：
1. 基础常识边界：仅允许调用大学预科及通识阶段的基础生物学与基础生理学常识（例如：细胞基本构造、酶具有催化特异性、受体结合介导信号转导等宏观公理）。
2. 严禁专家知识代偿：对于特定疾病的病因、罕见突变、复杂病理级联、特异性药物靶点及具体病例的未公开数据，探针严禁调取大模型底座的外部先验知识进行“脑补”或越俎代庖式代偿。
3. 信息隔离：探针在检查点所掌握的视野，严格仅限于当前输入的前缀材料。尚未到达的后文、作者教案备注（teacher_notes）、既往评审意见、额外答案标签及未来题目答案不得进入探针。已到当前断点的真实口播答案必须原样保留，不能因为它是答案删掉。
4. 机制理解考核基线：对机制因果链的考核，核心在于能否以白话讲清“谁对谁做什么、下一步为何发生（Who does what to whom, and why does the next step happen）”。单纯复读或拼凑输入材料中的生僻术语不被视为理解，必须体现由动词和主客体驱动的动态因果传递。

三、输入视界与信息四分法原则
每次审核均针对截至当前断点的口播前缀输入。输入载荷包含任务类型 task_kind（spoken_context / visual_context / causal_understanding / novice_load / negative_control）、截至断点的前缀分块列表（prefix）、当前检视原话（focus_quote）以及中性理解提问（question）。当任务涉及画面状态（visual_context）时，严格仅提供该时点实际抽取的视频关键帧与此前已确认可见的状态日志；未渲染的分镜脚本（Storyboard）与规划性图源仅属设计意图，不得视作实发事实。
探针在解析材料时，必须严格区分并归纳以下四类信息：
1. 已观察到的患者事实：病例中已明确记录的主诉、现病史、体征及已回报的化验数值。必须严格遵守：纯粹的章节标题、通用疾病机制标签绝不等于具体患者在临床上已经获得该项检查结果。
2. 明确当地补充的新发现：讲者在当前断点句刚主动告知、引入的新事实或新辅助检查结果。教学允许信息的后置渐进披露，只要引入时不假定学员早已掌握，即属合规。
3. 从机制推导的新一般结论：基于已呈现的事实及基础通识，经由连续因果链一步步推演出的普遍生物学或药理学规律。中间步骤不得存在跨越式断层。
4. 明确宣布的新条件/新练习题：进入变体病例、分支假设或课堂测试题时，讲者显式声明的新虚拟条件。必须有明确的语意转折或题干宣布，不可与原病例事实混淆。

四、首次依赖（First-Dependency）审查法则
当讲稿出现病例发现、关键化验、特异性药物、专业术语、对比对照条件、代词指代或明确指认画面局部元素时，若该元素被当作“受众已知的前提条件”加以运用，必须进行首次依赖穿透审计：
1. 独立原子化追溯：每一个前提依赖必须作为独立原子项提取并记录。严禁将多项概念打包合并，严禁选用较晚处的重复提及作为出处来掩盖最早出现时的认知空缺。必须精准记录最早被依赖处的原话（use_quote）与最早交代处的原话（source_quote）。
2. 依赖状态五元判定：
   - established_before：该事实此前已在明确的上下文（source_chunk_id）中被清晰交代；
   - introduced_here：在当前句中首次作为新概念被明确定义或引入，未预先预设受众已知；
   - derived_here：基于已有事实，在当前句通过严密因果逻辑推导得出；
   - missing：未经前文交待或推导，直接假定受众已知该未公开事实，构成认知断裂缺口；
   - unclear：代词指代不明、语意含混或画面指涉歧义，导致依据链条无法确证。

五、合规判定与教学宽容度边界
本协议旨在保障教学合理性而非限制创作，必须严格区分“真实逻辑缺口”与“合规教学节奏”：
1. 首句与开篇豁免：课程首句或新章节导言通常承担破题、建立兴趣或引出全局宏观问题的职能，正常情况下不要求句前已有铺垫，严禁因全课答案尚未揭晓而判开篇失败。
2. 探究式悬念放行：讲者抛出全局问题后逐步展开病史与推导，属于正规教学节奏；只要当前断点处未强行要求学员依据尚未给出的材料回答未来阶段的深层机制，便不构成违规。
3. 术语适度保留：复述与解释（teach_back）应当采用通俗语言重构动作流，但允许规范性保留学科必要的核心解剖与生化名词，只要该名词已被定义或不影响因果主干，不得判定为专家代偿。
4. 判定级别分流：凡不阻塞当前认知目标、属于讲者修辞习惯或细微语感偏好的内容，统一归入 optional_notes，维持 verdict 为 pass；唯有在存在确凿 missing 且该缺失阻断了对 focus_quote 的连贯理解或导致中性题无法作答时，方可判定为 revise 并提炼 required_edits。

六、阴性对照与探针失效隔离机制
在 task_kind 为 negative_control 的任务下，用于检验模型是否具备严格依托材料拒答超纲问题的能力：
1. 诚实拒答准则：当中性提问涉及输入前缀未包含的高阶机制、未列出的检查或未来预后时，探针必须如实判定 answerable_from_material 为 false，answer 与 source_quote 返回 null。明确指出当前材料信息不足，坚决杜绝依赖预训练专家经验强行解答。
2. 探针失效（Probe Invalidation）隔离：若在阴性对照中，探针凭借底座强大的医学预训练参数擅自拼凑出了医学上正确但材料中完全未给的答案，该现象在工程上被定义为“审核证明失效（探针保真度崩溃）”。工程管线应记录探针失真事件并剔除该次评估，严禁直接以此判定教学讲稿存在质量缺陷。

七、判定裁决、边界限制与校准申明
探针的最终审核输出必须严格依托当前输入，给出符合规范的结构化评估：
1. verdict 裁决：pass（无致命认知缺口，因果自洽）、revise（存在阻断当前教学目标的硬缺口，需必要修改）、uncertain（受制于指代不清或证据截断无法给出确定判断）。
2. limits 局限性申明：探针必须主动声明当前裁决受限于前缀截断长度、静态抽帧清晰度、单向文本流及未见视频成片等客观边界。
3. 工程校准边界：本协议为质检语言规范与逻辑判定参考基准。基于有限正反例进行的阶段性盲测校准，无法从统计上担保所有未来新课一次性完全通过。工程实施应依据本协议规范开展自动化判定与持续迭代，严禁引入虚构的毫秒级时间戳，严禁设置僵化的字数、帧数或死板的分数阈值。


八、来源忠实性与引用编号约束
附录：复述语义忠实度与断言溯源规程

一、来源与量词转移红线
审核探针即使正确命中主缺失标签，若在复述中发生“来源/量词转移”——将输入中仅用于解释机理的普遍疾病特征升级为“本例患者已查出体征”，或擅自脑补未交代的化验结果、药物、时间节点及病人条件，一律判定为审核证明失效，严禁用主标签命中率掩盖复述失真。无据可循时必须明确声明信息缺失，严禁为追求语言流畅将其改写为虚假病例。

二、引用解耦与结构化断言体系
工程接口为输入前缀的分句分配不可变引用ID，探针仅负责选取use_ref与source_ref，原文由外部脚本精确还原。复述必须采用claims数组呈现并严格声明属性：
1. patient_observation：必须具备明确的患者事实来源，通用机制原句仅支持机制说明，严禁挪作患者实测；
2. general_mechanism：仅限支持通识机理说明，严禁附会为个案状态；
3. inference：必须显式标注为推论并列出已讲明的前提，严禁伪装为既成化验；
4. missing_information：材料未交代时须如实标注缺项。
探针仅允许调用简单基础生物常识辅助解释，严禁调用专家级病种先验知识填补病例空白。

三、教学宽容度与工程核验边界
本附录恪守教学规律：继续允许概念首次定义、破题引导与后续机制推导，不强求开场装满全部事实，亦不要求在每个医学概念后机械增加免责声明。
工程接口仅保证ID引用合法性与时间顺序，无法自动判定语义蕴含真伪。系统仍须依托未暴露标签的历史正反例与阴性对照，盲测检验语义正确性与复述来源忠实性，严禁将同模型多数票视作证明；基于有限样本的校准，亦不能担保所有未来视频毫无差错。


1. 范围聚焦与因果提炼：仅提取当前审核 focus 及其在当前段落成立所必需的直接因果链条，通常提炼为 1–3 条有实质内容的 claims；严禁全盘复述前缀背景、整个课程或与当前判定无关的机理。
2. 条件保真与程度限定：每条 claim 必须严格保留原话的主体、特定前提条件（如特定病理、生理或实验条件）及程度限定；严禁省略触发条件而导致推论被普遍化，严禁擅自升级或漂移程度词（如不得将相对减少改写为绝对耗竭，不得将条件性受阻泛化为常态发生）。
3. 证据闭环与诚实溯源：所选 source_refs 组合必须能够作为整体完整支撑该 claim 的所有因果要素；若推导依赖早期前提，必须追溯并引用对应的前文真实 ref，严禁引用不支持该主张的条目或依赖未说明的常识脑补；若上游资料不足，必须如实标注为信息缺失（missing_information），严禁强行构造解释。
4. 字段规范（learner_question）：凡依赖关系已解决（established_before、introduced_here、derived_here）的 claim，其 learner_question 必须严格输出为 JSON null；仅在依赖缺失（missing）或逻辑未明（unclear）时，填入具体的理解卡点与疑问。
5. 审查底线与负控原则：本补充规则旨在消除非任务冗余与格式瑕疵，不限制应发现的问题数量，绝不削弱对病例观察事实的核验与首次依赖项检查，绝不得以精简输出掩盖推理断层；对负控用例与无效推导，必须保持独立并诚实拒答或指出逻辑漏洞。
