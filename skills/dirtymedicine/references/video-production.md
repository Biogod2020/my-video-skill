# 视频制作落地规范与状态机 Schema

面向绘图、合成工具或代码渲染（如 Remotion、MoviePy、剪辑脚本）的可执行分镜交付参考。本规范提供自洽的概念分镜协议，不假装特定渲染引擎已存在特定 API。若项目已有脚本格式或模板，优先对接项目现有格式。

## 0. 分镜与图解的 Gemini/agy 协同机制
- **分镜与提示词由 agy 规划**：分镜表、视觉演进动作、GPT Image 生图提示词及图像不变量由 agy 统一撰写，确保分镜完全匹配口播意图。
- **生成图解由 Gemini/agy 审核**：GPT Image 工具生成图像后，**必须将实际图像文件连同对应口播台词交付 Gemini/agy 审核**，重点检查医学科学拓扑、空间朝向、文字可读性与教学表达效果。
- **Codex 工程核验与接入**：Codex 负责核验原生代码图层（数学公式、反应箭头、倒计时组件、动态高亮框等），核对实体数量、图层遮挡与实际时间线接入。

## 1. 图解负责教与生图边界
- **图解覆盖与独立视觉**：医学系列必须设计独立封面；关键机制、横向比较、临床表现及总结页应尽量配置专门的高质量图解。不设定生图张数上限，以知识讲透为准。
- **生成图与代码原生层分工**：
  - GPT Image 负责生动的直观形态、解剖/病理演变场景与生活助记物象（如双凹盘红细胞、包涵体沉淀、巨噬细胞吞噬场景、助记实物）。
  - 精确生化公式、文本卡片、引导箭头、计时器、选项按钮与动态高亮框，优先采用代码或渲染引擎的原生图层进行精确绘制与控制；必要时整张 slide 生成后再严格核验。
- **图像不变量**：医学实体数量、箭头流动方向、反应化学计量、实验条件与临床路径，均须作为图像不变量严格锁定，绝不把“画面美观”等同于“医学正确”。
- **避免解剖误导**：机制图明确标为机制示意图，切忌将机制示意图伪装为真实组织学切片。

## 2. 空间一致性与动线控制
- **音画方位严格对齐**：必须把口播提到的左右、上下、前后等方位词，与实际图像位置逐一核对。口播讲右侧模型，画面实体就必须在右侧，彻底清除误导性的陈旧占位字符。
- **标签就近附着原则**：催化酶与电子供体等说明卡片，必须物理就近放置在实际作用位点旁，消除视线交叉折返疲劳。
- **微缩总览与拓扑接续**：跨页面展示分支代谢时，在接入端使用微缩卡片承接前页支路，引出箭头指向输入端，打通全局拓扑关系。
- **焦点管理**：每次重点保留当前讲解对象，旧的高亮框与指示动效及时退场，避免视觉信息饱和杂乱。

## 3. 屏幕短标签与字幕安全区
- **屏幕短标签原则**：屏幕标签仅保留实体名称、生化动作与核心结论。深入解释留给口播，不堆砌长篇解释性段落。
- **字幕安全区核验**：字幕底部安全边距依据最终字号大小和实际渲染帧决定；严禁将固定百分比当作验收替代，必须在实际终端帧上检查是否遮挡核心图文或注音。
- **短字幕排版与断句**：短字幕单行长度适中（通常 ≤16 汉字），保留英文缩写和中英术语，严禁将一个医学专有名词从中间生硬切断。
- **题目呈现规范**：题干和选项文字清晰可读；题目呈现时严禁提前标红答案或在背景图中泄露答案。

## 4. 题目交互与倒计时设计
- **安静思考期呈现**：正式练习题读完题干与选项后，画面正中下方展示醒目的半透明动态胶囊栏（如 `[ ⏸ 建议暂停思考 | 倒计时 5s ]`），伴随平滑递减进度条与柔和提示音。
- **平稳揭晓答案**：倒计时结束后，口播先给出自然过渡句（如“好，我们来看答案”），随后选项高亮框与正确对勾才亮起，消除仓促催促感。

## 5. 时间轴 Cue 触发与音素匹配
- **依靠真实音频**：初稿中的 cue 仅标注顺序和文本触发点，绝不虚构精确秒数；时间点最终必须依靠生成后的真实音频波形去测算和对齐。
- **字级对齐边界**：ASR 识别字级匹配不保证医学名词读音绝对正确，也不等于音素级别时间的完美挂靠。遇到关键问题和答案揭晓，相关的停顿段（如思考留白）要被独立识别标出，确保“旁白发声开始后”才在画面上揭晓答案。后期微调音频后，所有字幕、章节轴和 cue 须全部重算。

## 6. 分镜段落交付 Schema 规范

每个分镜段落作为一个独立的结构化单元交付：

```yaml
segment_id: "SEG-01"
decision_point: "判断目标：向学习者解释红细胞内清除过氧化氢时 GPx 的催化作用与 GSH 的氧化转化"
suggested_duration: "约 15–20 秒（建议排程，以实际配音校准）"
voiceover: "红细胞处理过氧化氢时，催化反应的是谷胱甘肽过氧化物酶，也就是 GPx。它使用两个还原型的 GSH，把过氧化氢还原成水。在这个反应里，GSH 献出了还原能力，两个分子自身被氧化结合，变成了 GSSG。"
screen_state: "居中呈现红细胞轮廓与反应物，随着口播逐步出现催化箭头与产物。"
elements:
  declared:
    - id: "cell_rbc"
      type: "shape_outline"
      label: "红细胞轮廓"
      initial_visible: true
    - id: "node_h2o2"
      type: "badge"
      label: "H2O2 (过氧化氢)"
      initial_visible: true
      position: { x: 300, y: 180 }
    - id: "node_gsh"
      type: "badge"
      label: "2 GSH (还原型谷胱甘肽)"
      initial_visible: true
      position: { x: 180, y: 280 }
    - id: "arrow_gpx"
      type: "catalytic_path"
      source: ["node_gsh", "node_h2o2"]
      target: ["node_gssg", "node_h2o"]
      label: "GPx (谷胱甘肽过氧化物酶)"
      initial_visible: false
    - id: "node_h2o"
      type: "badge"
      label: "2 H2O (水)"
      initial_visible: false
      position: { x: 300, y: 380 }
    - id: "node_gssg"
      type: "badge"
      label: "GSSG (氧化型谷胱甘肽)"
      initial_visible: false
      position: { x: 420, y: 280 }
  reused: []
cues:
  - at_word: "谷胱甘肽过氧化物酶"
    action: "reveal"
    targets: ["arrow_gpx"]
  - at_word: "还原成水"
    action: "reveal"
    targets: ["node_h2o"]
  - at_word: "变成了 GSSG"
    action: "reveal"
    targets: ["node_gssg"]
    updates:
      - target: "node_gsh"
        style: "dimmed_consumed"
short_labels:
  - text: "催化：谷胱甘肽过氧化物酶 (GPx)"
    target_id: "arrow_gpx"
  - text: "2 GSH + H2O2 → GSSG + 2 H2O"
    target_id: "cell_rbc"
assets:
  - id: "diag_gsh_pathway"
    type: "schematic_2d"
    status: "to_create"
    spec: "2D 矢量机制示意图（明确标明为示意图，非显微切片），展示底物、产物及催化酶"
```

### Schema 规范要求
1. **口播 Cue 对应**：`cues` 中的 `at_word` 必须字面出现在本段 `voiceover` 文案中，作为驱动视觉动作的时间锚点。
2. **元素生命周期**：所有图形节点在首次出现的段落中由 `declared` 声明；后续段落如需继续操作，放入 `reused` 并引用其已有 ID。
3. **初始可见性**：后出场或伴随特定词语揭晓的元素，必须在 `declared` 中显式指定 `initial_visible: false`，由对应的 `cue` 执行 `reveal`，避免画面未讲先出。
4. **反应拓扑守恒**：生化转化路径必须明确声明 `source` 底物与 `target` 产物，反应进出保持守恒。
5. **台词时序与显现对齐**：按最终口播从头走一遍，表格、标签、答案的出现顺序和实际台词一致；节点先显示再高亮，引用先定义，不只检查字段存在。单元格按实际讲到的次序显现，不能只排一套自洽目录却让台词矛盾。
