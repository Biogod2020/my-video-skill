# 视频制作落地规范与状态机 Schema

面向绘图、合成工具或代码渲染（如 Remotion、MoviePy、剪辑脚本）的可执行分镜交付参考。本规范提供自洽的概念分镜协议，不假装特定渲染引擎已存在特定 API。若项目已有脚本格式或模板，优先对接项目现有格式。

## 1. GPT Image 生图边界与提示规范
- **生图应用场景**：对比展示页、形态病理因果演变、病例解释应采用生动大图；纯精确的表格、公式或流程箭头仍推荐纯文本配合代码绘制，不必强制所有画幅都去生图。
- **提示词要素**：生图 prompt 必须写明：医学实体拓扑关系、左右空间分布、箭头方向、角色分工、单位与标签、隐喻界限限制，及预留最终字幕叠放的安全区和分步显现需求。
- **图像核查**：生成后必须逐项人工检查中文/英文文字、反应化学计量、方向和底层逻辑。绝不把“画面美观”等同于“医学正确”。
- **避免解剖误导**：采用助记比喻或机制示意时，明确标为机制示意图，切忌扭曲真实的解剖或组织学结构（如泵的方向应准，去除错误且无关的杂物离子）。

## 2. 时间轴 Cue 触发与音素匹配
- **依靠真实音频**：初稿中的 cue 仅标注顺序和文本触发点，绝不虚构精确秒数；时间点最终必须依靠生成后的真实音频波形去测算和对齐。
- **字级对齐边界**：ASR 识别字级匹配不保证医学名词读音绝对正确，也不等于音素级别时间的完美挂靠。遇到关键问题和答案揭晓，相关的停顿段（如思考留白）要被独立识别标出，确保“旁白发声开始后”才在画面上揭晓答案。后期微调音频后，所有字幕、章节轴和 cue 须全部重算。

## 3. 真实视频验收
- **以最终 MP4 为准**：静态画面就绪 ≠ 视频完成。最终验收必须播放实际完整生成的 MP4 视频，复查新的图像、中英字幕对齐、前后关键帧呼应、真正片尾留白是否完整，以及尾音是否被切断。
- **杜绝主观臆测**：绝不可仅凭代码执行路径或输出参数就断定听感良好。所有的技术论证与日志记录归入生产附录，不在呈现给学生的可见字幕或主画面里展示。


## 4. 分镜段落交付 Schema 规范

每个分镜段落作为一个独立的结构化单元交付：

```yaml
segment_id: "SEG-01"
decision_point: "判断目标：向学习者解释红细胞内清除过氧化氢时 GPx 的催化作用与 GSH 的氧化转化"
suggested_duration: "约 15–20 秒（建议排程，以实际配音校准）"
voiceover: "红细胞处理过氧化氢时，催化反应的是谷胱甘肽过氧化物酶，也就是 GPx。它使用两个还原型的 GSH，把过氧化氢还原成水。在这个反应里，GSH 献出了还原能力，两个分子自身被氧化结合，变成了 GSSG。"
screen_state: "居中呈现红细胞轮廓与反应物，随着口播逐步出现催化箭头与产物。"
elements:
  declared:
    - id: "cell_rbc"
      type: "shape_outline"
      label: "红细胞轮廓"
      initial_visible: true
    - id: "node_h2o2"
      type: "badge"
      label: "H2O2 (过氧化氢)"
      initial_visible: true
      position: { x: 300, y: 180 }
    - id: "node_gsh"
      type: "badge"
      label: "2 GSH (还原型谷胱甘肽)"
      initial_visible: true
      position: { x: 180, y: 280 }
    - id: "arrow_gpx"
      type: "catalytic_path"
      source: ["node_gsh", "node_h2o2"]
      target: ["node_gssg", "node_h2o"]
      label: "GPx (谷胱甘肽过氧化物酶)"
      initial_visible: false
    - id: "node_h2o"
      type: "badge"
      label: "2 H2O (水)"
      initial_visible: false
      position: { x: 300, y: 380 }
    - id: "node_gssg"
      type: "badge"
      label: "GSSG (氧化型谷胱甘肽)"
      initial_visible: false
      position: { x: 420, y: 280 }
  reused: []
cues:
  - at_word: "谷胱甘肽过氧化物酶"
    action: "reveal"
    targets: ["arrow_gpx"]
  - at_word: "还原成水"
    action: "reveal"
    targets: ["node_h2o"]
  - at_word: "变成了 GSSG"
    action: "reveal"
    targets: ["node_gssg"]
    updates:
      - target: "node_gsh"
        style: "dimmed_consumed"
short_labels:
  - text: "催化：谷胱甘肽过氧化物酶 (GPx)"
    target_id: "arrow_gpx"
  - text: "2 GSH + H2O2 → GSSG + 2 H2O"
    target_id: "cell_rbc"
assets:
  - id: "diag_gsh_pathway"
    type: "schematic_2d"
    status: "to_create"
    spec: "2D 矢量机制示意图（明确标明为示意图，非显微切片），展示底物、产物及催化酶"
```

### Schema 规范要求
1. **口播 Cue 对应**：`cues` 中的 `at_word` 必须字面出现在本段 `voiceover` 文案中，作为驱动视觉动作的时间锚点。
2. **元素生命周期**：所有图形节点在首次出现的段落中由 `declared` 声明；后续段落如需继续操作，放入 `reused` 并引用其已有 ID。
3. **初始可见性**：后出场或伴随特定词语揭晓的元素，必须在 `declared` 中显式指定 `initial_visible: false`，由对应的 `cue` 执行 `reveal`，避免画面未讲先出。
4. **反应拓扑守恒**：生化转化路径必须明确声明 `source` 底物与 `target` 产物，反应进出保持守恒。
5. **台词时序与显现对齐**：按最终口播从头走一遍，表格、标签、答案的出现顺序和实际台词一致；节点先显示再高亮，引用先定义，不只检查字段存在。可以为表格预留所有位置，用户已指定的排列也可保留，但单元格按实际讲到的次序显现，不能只排一套自洽目录却让台词矛盾。

## 5. 视觉演进与画面控制

### 1. 元素标识与坐标稳定性
- 全片复用元素使用全局语义 ID（如 `node_g6pd`、`table_aphasia_row_broca`）。
- 在同一段机制推演或同一张对比表中，主体元素与坐标排布保持稳定，避免因镜头随意晃动增加重新定位的认知负担。
- 若因教学阶段变化需要切换版面，口播中应有承上启下的引导。
- 画面动作也属于知识解释，要对照口播和公式；若文字说浓度固定，图上就保持其数值不变，只改变这次实验操纵的条件。

### 2. 屏幕短标签原则
- **短标签定位**：屏幕标签仅保留实体名称、生化动作与核心结论（例如：“Vmax 不变”“表观 Km 增大”“C 肽：内源伴生”）。
- **解释留给口播**：避免在画面标签中堆砌长篇解释性段落；标签负责在视觉上定住判据，口播负责讲清因果。

### 3. 排程与对齐控制
- 在没有实际录音音频前，脚本排程仅注明“建议时长”，排程逻辑以口播词 cue 与先后动作为准。
- 录音完成后，可通过时间轴字幕、强制对齐（forced alignment）或音频波形校准具体呈现时间，不强制单一实现方式。

## 6. 素材类型与可核查状态

### 1. 素材核查与分级标识
- **状态区分**：按本地实际文件状态标注为“已有”（existing）、“待获取”（to_fetch）或“待制作”（to_create），仅在制作备注中记录流转状态，不要求在面向观众的画面字幕中显示待获取流程。
- **真实临床素材**：使用血涂片、影像或切片时，若染色方法与成像技术明确，在制作备注中记录（如 Wright-Giemsa 染色）；若未确认或本地未下载，在制作备注中记为“待核实/待获取”，严禁主观推测。

### 2. 机制示意图（Schematic Diagrams）
- **适用**：表达因果拓扑、分子通路、动力学曲线与对比矩阵。
- **标识规范**：界面明确标明为机制示意图，不可伪装为真实组织学图片。
