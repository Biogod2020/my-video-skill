# 批量讲稿生成与定标质检规范 (Batch Authoring & Automated Verification)

本规范定义基于 DSH 与自动化评估的 10–12 分钟中英文医学教学讲稿批量生产流程、定标质检标准及工程收敛协议。旨在确立统一客观的质量底线，减少逐稿人工微调，实现可控的工业化生产。

本层筛选讲稿候选；通过后继续执行既有七项文稿门禁和实际音视频审核。

---

## 1. 课程范围契约与冻结机制 (Scope Contract)

在启动任何新课讲稿编写前，必须依据原教学总纲与用户已确认的需求范围，显式冻结一份三级范围契约（`scope_contract.json`），明确划定教学内容边界：

1. **三级教学内容分级**：
   - **核心范围 (`core`)**：本课必讲且必须达成闭环的核心生化转化、酶/蛋白缺陷机制、特征性病理生理改变、第一例典型体征/化验推导及核心试题解析。未讲或讲错构成绝对阻断。
   - **支持范围 (`support`)**：支撑核心机制理解所必需的正常生理基线、必要转场铺垫、化验指标基础含义及选项横向鉴别点。根据叙事需要合理编排。
   - **可选范围 (`optional`)**：次要并发症、罕见分型变异、细枝末节的旁系反应或延伸学术探讨。**此类内容一律归入 `optional_notes`（教师备注/讲义附录），严禁自动追加至正文口播必讲内容中**。
2. **正文范围外免责与判定解耦**：
   - 严格遵循契约范围审核，**讲稿未涉及契约范围之外的边缘医学知识，绝对不得作为扣分依据**。
   - 严禁审查模型利用未列入契约的百科常识“为讲稿加戏”或以此挑刺判定讲稿残缺。

## 2. 文本篇幅与时长预算基线 (Duration & Lexical Budget)

本流水线面向 **10–12 分钟（600–720 秒）** 的标准教学微课。篇幅预算基于同语言、同语音配置文件（Voice Profile）的真实物理发声速度与自然停连实测数据换算：

1. **实测基线与换算预算**：
   - 每语言独立使用同 voice profile 已生成母带的“原生总秒数 / 正文单位数”。原生总时长含自然停连，不能冒称扣静音后的发声速度。
   - 中文按汉字及拉丁术语单位、英文按词计数，计数实现以 `scripts/course_authoring.py` 为准；已冻结的显式思考时长另计。
   - `起稿目标 = (目标区间中点 − 思考时长) / 单位秒数`；`篇幅上限 = floor((区间上限 − 思考时长) / 单位秒数)`。配置、样本哈希与预测区间随任务归档，不把本次样本数值硬编码为所有课程语速。
   - 平均预测只指导写作，实际音频生成后重新测量；不能保证精确片长。
2. **多语种独立创写原则**：
   - 中文与英文讲稿必须针对各自语种受众（中文面向本土初学者，英文严格对照 B02 IMG 简化版基准）分别独立撰写与优化。
   - **严禁机械按中文篇幅直译或强行对齐段落字数**；英文重在短清因果与精准专名，中文重在比喻生动与语流承接。
3. **篇幅调控与剪辑红线**：
   - **过长处理**：首选精简无实际因果增量的修饰词、压缩重复出现的非核心交代、剪除非必需支线；**坚决禁止为了压缩篇幅而删去分子动作、反应条件或必要因果推导台阶**。
   - **过短处理**：应检查是否遗漏了核心机制推导或解题铺垫，**坚决禁止机械填充废话套话凑字数**。
4. **音频合成与时间线绝对禁令**：
   - **保留试题 4 秒思考停顿**：严格保留用户要求并标定的正式练习题答案揭晓前 4 秒留白计划。
   - **禁止给 MOSS-TTS 设定硬性 duration 约束**，禁止采用全局倍速（Global Tempo Stretching）拉伸或压缩音频，禁止通过逐句 R3 时间扭曲来迁就时长。
   - 句间停顿与真实音质只能在后续媒体阶段进行物理测量与实听，文稿评分阶段不得凭空猜测或宣称听过音频。

## 3. 固定八维标准与 20 项验收条目 (Twenty Fixed Verification Items)

流水线沿用项目基准的八个教学维度权重配置：`medical_accuracy: 20`, `causal_closure: 20`, `sequence_context: 15`, `cognitive_load: 15`, `spoken_naturalness: 15`, `mnemonic_usefulness: 5`, `exercise_teaching: 5`, `visual_teaching: 5`。

新流水线以 **20 条固定、须附证据的验收项**（每项基准 5 分）替代主观模糊的 0–10 印象分打分。评审模型逐项输出 `pass`、`fail` 或 `uncertain`，并提供当前稿的逐字原文证据；最终综合得分由确定性工程脚本计算。

### 3.1 评分与适用性契约
- **适用性触发 (`applies_when`)**：分为 `always`（通用项）、`has_hook`（含口诀项）与 `has_exercise`（含习题项）。若课程契约未配置口诀或习题，对应项不激活，满分分母相应扣减，**绝不强加不必要的口诀或练习，亦不因无口诀扣分**。
- **阻断属性 (`blocking`)**：医学、因果、前置关键依赖项为 `blocking: true`。任一阻断项判定为 `fail` 即构成致命硬伤，无论总分多高均不得放行候选。
- **存疑隔离机制 (`uncertain`)**：若引据不足或模型无法确证，标记为 `uncertain` 并进入异常队列；**未获证据支持的存疑不得作为已证实医学错误去随意改动讲稿**。
- **证据引用法则**：扣分必须精确绑定当前稿的逐字真实引文及 `paragraph_id`；涉及缺失类问题必须通读完整当前稿核实确属全篇缺失，严禁凭空捏造连续引文。
- **教学与自然度底线**：坚持师生指图对话语境；严禁设立机械词语黑名单、严禁强制极短句断裂、严禁硬性规定每页固定行数；必须将科学事实准确性与认知负荷严格解耦。

## 4. 控制器返修与收敛协议 (Revision Controller & Convergence Protocol)

为避免无休止试错与自动化漂移，控制器实施严格的有限状态收敛协议：

1. **返修轮次上限**：最多执行 **2 轮实质返修**。若 2 轮后仍未达到放行标准，立即终止自动化循环，将完整上下文归档并转入人工复核队列。
2. **会话隔离与完整上下文**：每一轮返修必须启动**全新的独立会话**，输入完整当前稿、契约范围、必要事实底稿及上一轮结构化反馈清单。严禁在旧会话中单句追问或增量修补。
3. **凭据归档与反作弊禁令**：
   - 全量持久化保存每一轮的原始讲稿、评审回执（包括 requested model、actual returned model、request ID 及 SHA-256 哈希）。
   - **严禁在遭遇负评或 fail 时通过同提示词重新抽样‘刷出 PASS’**。
   - 相同文本哈希绝不重复运行语义评分；网络或 Schema 格式等技术失败单列计数，有限重试（当前控制器为 0 次，失败隔离；若启用重试另行配置版本），超限立即隔离报错。
4. **版本冻结与历史回归**：
   - 评分标准、提示词或校准集变更必须升级规则版本号，严禁追溯篡改历史得分。
   - 采用已知正反用例进行历史回归验证（Historical Regression），如实记录通过与失败案例，**严禁将已曝光测试样本虚标为未见 Holdout 数据**。
   - 正式批量启用前，必须经过至少 2 个不同医学主题的试产检验，验证通过后方可正式量产。

## 5. 门禁流水线集成与自动化交接 (Pipeline Integration & Quality Gates)

1. **候选层角色定位**：
   - 本流水线仅负责生成高质量**候选讲稿（Draft Candidates）**。它不是终审裁决，更不得复制或替代现有的统一发布门禁体系。
2. **衔接既有质检门禁**：
   - 生成的候选讲稿必须严格消费当前讲稿哈希，接入 `scripts/course_qc.py script-review` 既有的七项门禁（author, medical, learner, comparison, prefix, calibration, source_audit）。
   - 严禁任何 QC 适配器默认直通（All Passed），严禁用旧清单或旧哈希产物替代新稿。
   - 任何未接通或未实际执行的质检步骤必须标记为 `NOT_RUN`，并坚决阻断进入后续配音与视频渲染阶段。
3. **自动化执行与人工介入边界**：
   - 正常符合标准的课程讲稿全自动流转，无需在每个中间步骤停下来向用户索要确认。
   - 仅在出现不可调和的逻辑冲突、真实医学存疑（`uncertain`）、阻断项失败或返修上限耗尽时，才将问题列入待人工干预队列。

## 6. 本机执行推荐流程与阈值基线 (Local Execution & Baseline Recommendations)

### 6.1 推荐执行流程
1. **步骤一：契约冻结** -> 由工程或 agy 解析总纲，输出并校验 `scope_contract.json`。
2. **步骤二：双语生成** -> 调用 DSH（或指定写作模型）分别生成中、英文讲稿候选。
3. **步骤三：20 项自动评测** -> 调用指定评委模型（如 `gemini-3.8-flash-high`）按 20 项固定准则逐项审查，输出包含逐字引文的结构化结果。
4. **步骤四：脚本核算与返修路由** -> 由脚本校验引文存在性并计算综合得分：
   - 若达成放行阈值且无阻断项失败 -> 交付 `scripts/course_qc.py script-review`；
   - 若存在阻断项失败且返修轮次 < 2 -> 携带结构化反馈启动第二轮改写；
   - 若返修轮次耗尽或存在未决 `uncertain` -> 移交异常隔离队列。

### 6.2 推荐放行阈值建议
- **综合得分阈值**：候选讲稿加权折算总分 **≥ 90 分**（满分 100 分，按适用项动态归一化）。
- **关键项硬性要求**：所有 `blocking: true` 项目通过率必须达到 **100%**（零容忍容错）。
- **存疑项容忍度**：未决的 `uncertain` 项数量必须为 **0**；任何存疑必须被独立来源审计或人工核销。

> [!NOTE]
> 上述 90 分阈值与阻断规则为工程初始推荐基线，实际生产阈值必须在多主题历史回归集校准后最终固化，当前阶段不得轻率许诺稳定量产已经完全无风险达成。
## 本机入口与实际状态

评分条目的唯一机器配置为 `scripts/course_authoring.policy.json`（版本化保存），工程检查与计分为 `scripts/course_authoring.py`，批量入口为 `scripts/course_batch.py`。使用 `run --queue <queue.json> --out <project/private/new-run>`；各课分别声明 contract、完整 source_packet、DSH profile，可给 baseline_draft。输出含每轮稿件、原始回执、dashboard 与 exceptions。默认先单任务试产；独立任务可用 `--jobs 2`。

当前实现自动写作、独立评分与最多两轮返修。只有登记并实际执行既有 QC adapter 后，才可能进入 `SCRIPT_REVIEW_READY`；未登记则为 `CANDIDATE_PENDING_OFFICIAL_QC`，七项门禁不补写 PASS。本控制器没有自动配音、渲染或发布功能。同哈希重复返修、引文无效、模型失败与冻结输入变动均隔离；不靠重抽审稿消除有效负评。

90 分是待多主题校准的初始阈值。历史正反例只能称回归，不能称未见测试集；至少两个主题的试产和医学/前置遗漏反例检查完成后再扩批。
